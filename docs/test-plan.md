# 测试计划

## 目标与范围

验证用户认证、购物车、普通订单、模拟支付、取消回补、秒杀窗口、限购和并发库存一致性。所有实验面向本地 TradeLab，测试数据可重建。真实资金、物流、分布式容灾、跨机房一致性不在当前范围内。

## 业务规则

1. 金额使用整数分；客户端提交价格不能改变订单金额。
2. 普通商品走普通订单入口；秒杀商品走秒杀入口，不能进购物车。
3. 下单立即预占库存；待支付订单取消后回补；支付不再扣减库存。
4. pending 只能变成 paid 或 cancelled；终态不能互相转换。
5. 重复支付、重复取消返回当前结果，不重复执行副作用。
6. 下单必须提供 Idempotency-Key。相同用户、相同键、相同商品请求返回同一订单；更换请求内容返回 409。复用键会返回原订单的当前状态，包括 cancelled。
7. 秒杀每次只能一件；同一用户对同一商品最多一个 pending/paid 占用，取消后可重新抢购。
8. 活动有效区间为 `[starts_at, ends_at)`，使用服务端时间。
9. 用户只能读取、支付、取消自己的订单；其他用户访问订单返回 404。
10. 任一商品失败，整个订单事务回滚；购物车只在成功下单后移除对应条目。

## 风险与方法

| 优先级 | 风险 | 方法与判定 |
| --- | --- | --- |
| P0 | 库存超卖、订单无库存 | HTTP 并发 + SQL 守恒校验 |
| P0 | 越权操作他人订单 | 两用户分别读取、支付和取消 |
| P0 | 取消回补多次、支付取消冲突 | 多线程竞争 + 最终状态和库存断言 |
| P0 | 多商品中途失败造成部分扣减 | 第二商品库存不足，验证首商品和购物车未改变 |
| P1 | 重复下单、限购绕过 | 同键并发、不同键同用户并发 |
| P1 | 金额错误 | 多商品总额、客户端篡改价格 |
| P1 | 非法输入 | 0、负数、布尔值、小数、字符串、空值、重复商品 |
| P1 | 活动时间误判 | 未开始、已结束；精确边界列为手工补充检查 |
| P2 | 页面核心流程中断 | Playwright 从注册到支付/取消 |

## 数据与隔离

每个 API / UI 测试函数启动独立 HTTP 服务，使用临时 SQLite 文件和操作系统分配的随机端口；用户随机命名。并发测试通过线程屏障同时发起真实 HTTP 请求，不使用 mock 代替数据库行为。测试结束关闭服务，由 pytest 管理临时目录。

## 执行与准入

先运行全部接口回归，再运行 UI，最后在独立数据文件上压测。准入标准：自动化通过，无未解释 5xx；并发测试成功数、业务拒绝数符合设定，库存不为负且与有效订单守恒。性能实验须记录环境和负载参数；不预设未经测量的 QPS 或 P95 承诺。

CI 固定 Ubuntu 24.04，执行 Python 3.9 / 3.12 API 测试和 Python 3.12 Chromium 测试；避免 ubuntu-latest 升级后不再提供旧版 Python 构建。Locust 默认手动运行，避免共享 CI 资源波动造成性能结论失真。
